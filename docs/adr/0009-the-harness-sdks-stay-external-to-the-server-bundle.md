# The Harness SDKs Stay External To The Server Bundle

The server ships as a single file. `apps/server/vite.config.ts` sets `ssr.noExternal: true`, so everything but Node builtins is inlined into `dist/bin.mjs` and the shell can spawn it under Electron's bundled Node with nothing to rebuild (even the SQLite driver rides the built-in `node:sqlite`). The two harness SDKs are the sole exception: `EXTERNAL_RUNTIME_PACKAGES` keeps `@openai/codex-sdk` and `@anthropic-ai/claude-agent-sdk` out of the bundle, and `scripts/build-desktop-artifact.ts` puts them back as real installed packages — `HARNESS_PACKAGES` lands in the staged `release/app/package.json`, `pnpm install --prod` materializes them next to the bundle, and electron-builder's `asarUnpack` lists both scopes alongside `apps/server/**`.

The mechanism that forces this is resolution from a package directory. Neither SDK talks to a model itself; each locates and spawns a vendored platform binary relative to its own files. Codex resolves `@openai/codex/package.json` through a `createRequire` over its own `import.meta.url`, then the platform package, then `vendor/<target-triple>/bin/codex`; the Claude SDK resolves `@anthropic-ai/claude-agent-sdk-<platform>-<arch>/claude` the same way — a 245 MB single-file executable. Inlining either erases the directory that walk starts from. Unpacking is a second, separate requirement: exec needs a real inode, and Electron's patched `fs` can read out of an asar but cannot execute out of one, so a path resolved inside `app.asar` fails at spawn.

Bundling them is the obvious cleanup, and it fails in the worst available way. The probes in `apps/server/src/harness/codex.ts` and `claude.ts` set `installed` from `codex --version` / `claude --version` on PATH — a global CLI the SDKs never invoke. So the app reports a harness as installed while every `open` fails with `HarnessUnavailableError`. The break is invisible until analysis runs, and only in a packaged app.

Two constraints follow. The staged manifest reads each version from `apps/server/package.json`, resolving `catalog:` against `pnpm-workspace.yaml`, and refuses to build if the server stopped declaring a package the bundle externalizes — the packaged app runs the versions the repo pins. And the binaries are `os`/`cpu`-gated, so the staged install fetches only the build host's: every architecture needs its own build, verified packaged, per ADR-0006.
