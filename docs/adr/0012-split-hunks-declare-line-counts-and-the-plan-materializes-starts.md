# Split Hunks Declare Line Counts And The Plan Materializes Starts

When the analysis harness decides that one seed hunk mixes two concerns and belongs in two clusters, the plan it returns declares only each part's `oldLines`, `newLines`, and `home` — never an absolute start line. `PLAN_SCHEMA` in `apps/server/src/analysis/prompts.ts` gives a split part no start field to fill. `materializePlan` in `packages/journey/src/plan.ts` computes the starts itself: it initializes a cursor pair to the seed's own `oldStart`/`newStart` and advances it by each part's counts, minting `h12.1`, `h12.2`, … as it walks.

The trade-off is deliberate. Absolute line numbers are the single easiest thing for a model to get wrong, and a wrong one is not a visible failure — a part claiming to start three lines early does not error, it silently attributes real code to the wrong cluster, and the reviewer reads a narrative about lines that are not the lines on screen. Counts are locally checkable in a way starts are not: whether the parts sum to the seed is arithmetic the harness can do against `hunks.json`, and it is exactly the check `materializePlan` runs before accepting a split. A mismatch collapses the split back to the whole hunk and records a fallback that `isRepairableFallback` in `apps/server/src/analysis/Ingestion.ts` feeds back as a correction turn.

The cursor is also what makes the partition exact rather than approximately right. Each part's start is derived from the previous part's end, so the parts of a seed cannot overlap and cannot leave a gap; a refinement of the seed partition is a partition by construction. That is the property `packages/journey/src/coverage.ts` must later be able to prove — `validateHunkPartition` independently re-walks the same cursor, and `validateLineCoverage` recomputes the covered line set from scratch. `seed-split-mismatch`, `line-uncovered`, and `line-double-covered` are real guarantees rather than hopes about the model precisely because nothing upstream of them was ever in a position to violate them.

Reversing this — letting a part carry its own `oldStart`/`newStart` — would move the coverage guarantee out of the code and back into the prompt.
